一单一钥：拿证据退款，只暴露这一单

防换模型

协调器以新身份随机下单，在参考模型上重算比对。连续两次不符，暂停接单 24 小时。

防蹭中继

门户签发 1 小时有效的 Ed25519 凭证，写明设备 peer ID。凭证被偷了也用不了。

防伪造

Offer、Ticket、收据、Ack 全部签名。peer ID 本身就是公钥，无需额外的身份目录。

防超扣

计费按 Ticket 上的价格结算，不超过预留金额。复式账本启动时回放日志对账。

防撞库

密码用 Argon2id 存储，登录失败限流。管理员强制 TOTP 两步验证。

防网页注入

严格 CSP，无第三方资源。会话放在 HttpOnly + SameSite=Strict 的 Cookie 里。

我们不声称的事

  • 普通节点能读到 prompt。加密把信任边界移到了节点，只有 TEE 才能把运营者也排除在外。敏感内容请选 TEE 节点。
  • 协调器仍然是账本的可信方。它伪造不了收据和 Ack，但账本由它记录。
  • 抽检是概率性的。它让作弊长期不划算，但不保证每一单都被查到。

怎么用

同一个账户，既能卖也能买。

客户端在本地开一个 OpenAI 兼容端点。任何支持 OpenAI 协议的工具，改一下 base URL 就能用。

用模型

非流式响应在收据验证通过后才交给你；流式响应边到边转发，结尾附验证结果。

# 客户端登录后，本地端点就绪
curl http://127.0.0.1:9787/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"gemma-4-e4b","messages":[…]}'

# 响应头
X-Sharetoken-Verified: true

赚 credit

把本机 Ollama 里的模型共享出去。不需要公网 IP，节点经中继打通连接。

# 共享一个本地模型
sharetoken-prod share add gemma4:e4b -id gemma-4-e4b

# 上线接单，按实际 token 结算
sharetoken-prod up

# 查看收益
sharetoken-prod balance

架构

四个角色，职责彼此隔开。

转发流量的看不到内容，记账的不碰数据路径，管账户的不撮合交易。

用户

买家和卖家在同一个进程里。自动测 RTT，选最快的中继，中继故障时自动切换。

中继

有多个，只转发加密流量。读不到明文，不记账，只给持有效凭证的设备预约。

协调器

撮合、结算、争议和抽检。不监听任何端口，只能经中继访问，暴露面很小。

门户

注册登录、API token、设备绑定、账单和中继登记，就是你现在看到的这个网站。
