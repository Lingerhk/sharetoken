# Translations

**English** | [简体中文](zh-CN/i18n.md)

The landing page and the user portal (`/app/`) are available in 10 languages: English, Simplified and Traditional Chinese, Spanish, French, German, Portuguese, Russian, Japanese and Korean. The desktop client has two, English and Simplified Chinese (`data-langs="en,zh-CN"` in [`internal/client/ui/index.html`](../internal/client/ui/index.html)), and so does its tray menu ([`gui/tray_text.go`](../gui/tray_text.go)). The admin console is in Chinese only: `admin.html` pins `data-lang="zh-CN"`, so the same `common.js` runs there without a dictionary.

## How it works

Chinese is the source language, and the source text is the key: `tr('登录')`. Dictionaries are flat JSON, `{ "<Chinese source>": "<translation>" }`, one per bundle and language. Simplified Chinese needs no dictionary.

| Bundle | Pages | Dictionaries |
| --- | --- | --- |
| `site` | landing page, user guide navigation | `internal/portal/web/i18n/site/<lang>.json` |
| `app` | user portal, shared login | `internal/portal/web/i18n/app/<lang>.json` |
| `client` | desktop client | `internal/client/ui/i18n/client/en.json` only |

The language comes from `?lang=`, then from the saved choice (`localStorage.st_lang`), and otherwise it is English. The browser's or system's language does not choose it. The desktop client is the exception (`data-detect="system"`): without a saved choice, the system's first preferred language decides, any Chinese giving Simplified Chinese and everything else English. Its language menu lists the two.

`internal/portal/web/i18n.js` and `internal/client/ui/i18n.js` are identical copies of the runtime, and the `i18n.css` beside each styles its language menu. A test checks that both pairs stay identical.

## The user guide

The guide at `/docs/` is Markdown under `internal/portal/web/docs/<language>/`, listed in `internal/portal/web/docs-nav.json`. It exists in English and Simplified Chinese. Readers of other languages get the English guide, and Traditional Chinese readers the Simplified one, each with a note. The guide's navigation text is in the `site` bundle like everything else.

`go test ./internal/portal -run TestDocs` requires both languages to have the same headings, code blocks and links in the same order, every link to resolve, and every command and flag to exist in `cmd/sharetoken`.

To add a language to the guide, add its directory, add it to `docsLangs` in `internal/portal/docs_test.go`, and extend `docLang` in `internal/portal/web/docs.js`.

Browser test: `scripts/docs_ui_test.mjs`.

## Changing text

1. Put new text through `tr('…')` in one literal, or `parts('…{x}…', {x: node})` when it contains an element. Write whole sentences with `{placeholders}`; never concatenate pieces. Static HTML needs nothing: its exact text is the key. An element with inline markup gets `data-i18n-rich`, and only `<br>`, `<em>` and `<strong>` may appear in it.
2. Avoid sentences that depend on the plural form of a count. There is no plural engine. Write a label and a number, like `Jobs: {n}`.
3. Run `go test ./internal/portal -run I18n`. It lists every missing or stale key, every broken placeholder, and Chinese text that bypasses `tr()`. With `I18N_DUMP=<dir>` it also writes each bundle's source strings to that directory.

Browser test of every language: `scripts/i18n_ui_test.mjs`.

## Translation rules

The Chinese text is authoritative. The English dictionary shows the intended tone.

- Keep unchanged: `{placeholders}`, `<br>`, `<em>`, `<strong>`, `|` separators, `→`, `·`, numbers, command lines, and these names: ShareToken, sharetoken, OpenAI, Ollama, TEE, CSP, SHA-256, X25519, Ed25519, HKDF, AES-GCM, Noise, libp2p, Argon2id, TOTP, RTT, API, CLI, HTTP, URL, JSON headers and field names, `respHash`, `peer`/`peer ID`, Ack, Offer, Ticket, `prompt`, `token`/`tokens`, `credit`.
- Use one established rendering consistently for: relay (中继), coordinator (协调器), portal (门户), node (节点), buyer (买家), seller (卖家), job (作业), receipt (收据), dispute (争议), device (设备), ledger/bill (账单), two-factor authentication (两步验证).
- Security statements stay exactly as strong as the source, never stronger. Ordinary nodes *can* read prompts, the coordinator *is* the trusted ledger, audits *are* probabilistic. Do not soften or embellish them.
- Short labels stay short: buttons, table headers, badges and navigation sit in tight layouts.
- Address the user in a neutral, direct, informal but polite register, as a well-translated developer tool would.
