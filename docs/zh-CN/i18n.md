# 翻译

[English](../i18n.md) | **简体中文**

官网和用户门户（`/app/`）提供 10 种语言：英语、简体中文、繁体中文、西班牙语、法语、德语、葡萄牙语、俄语、日语和韩语。桌面客户端有两种，英语和简体中文（[`internal/client/ui/index.html`](../../internal/client/ui/index.html) 里的 `data-langs="en,zh-CN"`），托盘菜单也一样（[`gui/tray_text.go`](../../gui/tray_text.go)）。管理后台只有中文：`admin.html` 固定了 `data-lang="zh-CN"`，所以同一份 `common.js` 在那里不加载词典。

## 工作方式

中文是源语言，源文本就是键：`tr('登录')`。词典是扁平的 JSON，`{ "<中文源文本>": "<译文>" }`，每个 bundle、每种语言一个。简体中文不需要词典。

| Bundle | 页面 | 词典 |
| --- | --- | --- |
| `site` | 官网、用户指南的导航 | `internal/portal/web/i18n/site/<lang>.json` |
| `app` | 用户门户、共用的登录页 | `internal/portal/web/i18n/app/<lang>.json` |
| `client` | 桌面客户端 | 只有 `internal/client/ui/i18n/client/en.json` |

语言先取 `?lang=`，再取保存的选择（`localStorage.st_lang`），否则是英语。浏览器或系统的语言不参与选择。桌面客户端是例外（`data-detect="system"`）：没有保存的选择时，由系统的第一首选语言决定，任何一种中文都给简体中文，其余都给英语。它的语言菜单只列这两种。

`internal/portal/web/i18n.js` 和 `internal/client/ui/i18n.js` 是运行时的两份相同副本，各自旁边的 `i18n.css` 负责语言菜单的样式。有一个测试检查这两对文件保持一致。

## 用户指南

`/docs/` 的指南是 `internal/portal/web/docs/<语言>/` 下的 Markdown，目录列在 `internal/portal/web/docs-nav.json` 里。它有英语和简体中文两个版本。其它语言的读者看到英语版，繁体中文读者看到简体版，都带一条说明。指南的导航文字和其它内容一样在 `site` bundle 里。

`go test ./internal/portal -run TestDocs` 要求两种语言的标题、代码块和链接相同且顺序一致，每个链接都能解析，每个命令和参数都在 `cmd/sharetoken` 中存在。

给指南增加一种语言：增加它的目录，把它加进 `internal/portal/docs_test.go` 的 `docsLangs`，并扩展 `internal/portal/web/docs.js` 里的 `docLang`。

浏览器测试：`scripts/test/docs_ui_test.mjs`。

## 修改文案

1. 新文案放进 `tr('…')`，写成一个字面量；包含元素时用 `parts('…{x}…', {x: node})`。用带 `{占位符}` 的完整句子，不要拼接片段。静态 HTML 不需要处理：它的原文就是键。带行内标记的元素加 `data-i18n-rich`，其中只能出现 `<br>`、`<em>` 和 `<strong>`。
2. 避免依赖数量单复数形式的句子。这里没有复数引擎。写成「标签 + 数字」，例如 `Jobs: {n}`。
3. 运行 `go test ./internal/portal -run I18n`。它会列出所有缺失或过时的键、损坏的占位符，以及绕过 `tr()` 的中文文本。设置 `I18N_DUMP=<dir>` 时，它还把每个 bundle 的源字符串写到该目录。

所有语言的浏览器测试：`scripts/test/i18n_ui_test.mjs`。

## 翻译规则

以中文文本为准。英语词典体现预期的语气。

- 保持不变：`{占位符}`、`<br>`、`<em>`、`<strong>`、`|` 分隔符、`→`、`·`、数字、命令行，以及这些名称：ShareToken、sharetoken、OpenAI、Ollama、TEE、CSP、SHA-256、X25519、Ed25519、HKDF、AES-GCM、Noise、libp2p、Argon2id、TOTP、RTT、API、CLI、HTTP、URL、JSON 头和字段名、`respHash`、`peer`/`peer ID`、Ack、Offer、Ticket、`prompt`、`token`/`tokens`、`credit`。
- 下列术语各用一个固定译法，前后一致：relay（中继）、coordinator（协调器）、portal（门户）、node（节点）、buyer（买家）、seller（卖家）、job（作业）、receipt（收据）、dispute（争议）、device（设备）、ledger/bill（账单）、two-factor authentication（两步验证）。
- 安全方面的表述与源文本强度完全一致，绝不更强。普通节点**能**读到 prompt，协调器**是**受信任的账本，抽检**是**概率性的。不要弱化，也不要修饰。
- 短标签保持简短：按钮、表头、徽标和导航都处在紧凑的布局里。
- 称呼用户时用中性、直接、随意但礼貌的语气，就像一款翻译得当的开发者工具。
